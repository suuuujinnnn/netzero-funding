# 외부 API 요청 경계

현재 v4는 정적 목업이며 외부 API를 호출하지 않습니다. 다음은 데이터 연동이 생길 때 적용할 원칙입니다. `veily-web`의 Spring Boot 전용 URL, 응답 형식, 오류 코드, 인증 정책은 이 프로젝트의 계약이 아니므로 가져오지 않았습니다.

## 연결 원칙

- 화면 컴포넌트에서 제각각 `fetch`를 호출하지 않습니다. 실제 계약이 정해지면 `shared/api`에 공통 요청 경계를 두고 도메인별 요청은 해당 슬라이스의 `api`에 둡니다.
- API 기준 주소와 인증 방식은 제공될 서버 계약에 맞춰 정합니다. 브라우저에 노출되는 `NEXT_PUBLIC_` 환경변수에는 비밀값을 넣지 않습니다.
- 응답 봉투, 에러 코드, DTO는 실제 서버 명세를 확인한 뒤 타입과 검증을 작성합니다. 다른 프로젝트의 계약을 복사하지 않습니다.
- 사용자가 보는 데이터에는 로딩·오류·빈 상태와 재시도 가능 여부를 설계합니다.

## 연동 후보

| v4의 현재 값 또는 동작 | 실제 운영 전 결정할 사항 |
| --- | --- |
| 목표액·모금액·진행률 | 데이터 출처, 갱신 주기, 집계 기준 |
| 참여 건수·참여 내역 | 공개 동의, 표시명, 개인정보 처리, 확인 시점 |
| 계좌번호 복사 | 실제 수납 계좌의 확정과 공개 가능 여부 |
| 폼 제출 안내 | 실제 폼 URL 또는 자체 신청 흐름 |
| 기간·목표 전력량·REC 설명 | 최종 운영 수치와 문구 확인 |

데이터 출처가 정해지기 전에는 목업 데이터를 화면 모델에 명확히 표시합니다. API나 결제 성공을 흉내 내는 호출 코드는 추가하지 않습니다.
