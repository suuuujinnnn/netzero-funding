# 코드 작업 흐름

1. 요청의 범위와 완료 기준을 확인하고, 변경 전 `rg --files`와 `rg`로 가까운 코드와 문서를 찾습니다.
2. 기존 v4 구현, 공용 스타일, 자산을 살펴보고 필요한 최소 변경을 정합니다.
3. 관련 코드만 수정하고 사용자 변경을 보존합니다. 추측에 따른 API·전역 상태·의존성은 추가하지 않습니다.
4. `pnpm agent:verify`를 실행합니다. 검증 범위는 [테스트와 doctor](test-and-doctor.md)를 따릅니다.
5. 사용자에게 보이는 변경은 [UI 검증](ui-verification.md)에 따라 실제 브라우저에서 확인합니다.
6. 변경 파일, 검증 결과, 남은 제약을 정확히 보고합니다.

현재 `pnpm agent:verify`는 doctor·포맷·lint·타입 검사·빌드를 실행합니다. 도메인 단위 테스트는 테스트할 로직이 생길 때 연결합니다.
