# 프론트엔드 아키텍처

이 문서는 `veily-web`의 Feature-Sliced Design(FSD) 레이어 원칙을 넷제로 펀딩 화면에 맞게 옮긴 **구현 기준**입니다. Next.js 앱의 초기 설정은 마련했으며, 아래 기능별 구조는 v4 화면 구현 시 적용합니다.

## 기술 구성

- Next.js App Router, React, strict TypeScript, Tailwind CSS v4를 기본 구성으로 삼습니다. Vercel 배포는 이 구성을 기준으로 준비합니다.
- 실제 설치 버전은 `package.json`과 `pnpm-lock.yaml`에 기록합니다. `veily-web`의 버전이나 의존성을 그대로 복사하지 않습니다.
- shadcn/ui의 `new-york` 스타일과 CSS 변수, Lucide 아이콘을 기본 UI 설정으로 채택합니다. 실제 컴포넌트는 필요한 것만 추가하고 v4 디자인 토큰에 맞춥니다. 초기 설정은 `components.json`에 있습니다.
- 현재 백엔드/API 계약은 정해져 있지 않습니다. 모금액, 참여 내역, 계좌, 폼 연결을 API로 가정하지 않습니다.

## 디렉터리 구조

```text
src/
├─ app/                         # App Router 진입점, layout, 전역 설정
├─ views/                       # 라우트에 대응하는 화면 조합
├─ widgets/                     # 여러 화면에서 공유하는 큰 UI 단위
├─ features/                    # 사용자가 수행하는 기능
├─ entities/                    # 여러 기능이 공유하는 도메인 모델이 생길 때 추가
└─ shared/                      # 도메인에 독립적인 UI, 설정, 유틸리티
```

역할이 없는 레이어나 세그먼트는 빈 폴더로 만들지 않습니다. 현재 v4는 단일 화면이므로 `views/project`에서 화면을 조합하고, 탭 전환·계좌 복사처럼 독립적인 동작만 필요에 따라 `features/`로 분리할 수 있습니다. 여러 화면에서 재사용하지 않는 상단바를 `widgets/`로 미리 추출하지 않습니다.

## 레이어 책임과 의존 규칙

상위 레이어는 하위 레이어를 참조할 수 있고, 하위 레이어는 상위 레이어를 참조하지 않습니다.

```text
app → views → widgets → features → entities → shared
```

- `app`: Next.js 라우트 파일, `layout`, 전역 스타일과 실제 필요한 전역 Provider. `page.tsx`는 화면을 연결하는 얇은 진입점으로 둡니다.
- `views`: URL에 대응하는 화면을 조합합니다. FSD의 `pages` 역할이지만 Next.js의 `src/pages` 라우터와 충돌하지 않도록 `views`로 부릅니다.
- `widgets`: 여러 화면에서 그대로 쓰는 독립된 UI 덩어리입니다.
- `features`: 탭 선택, 계좌 복사, 향후 참여 신청처럼 사용자의 행동을 구현합니다.
- `entities`: 모금 프로젝트나 참여 내역 같은 도메인 모델을 여러 기능이 함께 쓸 때 추가합니다.
- `shared`: 특정 모금 도메인과 관계없는 UI, 설정, 유틸리티입니다.

같은 레이어의 다른 슬라이스를 직접 참조하지 않는 것을 기본으로 합니다. 슬라이스 외부에 노출할 코드가 필요하면 `index.ts`를 공개 API로 사용합니다. 슬라이스 내부에는 필요한 경우에만 `ui`, `model`, `api`, `lib` 세그먼트를 만듭니다.

## 새 코드 배치 기준

| 코드                                      | 위치 예시                                          |
| ----------------------------------------- | -------------------------------------------------- |
| 공통 버튼·다이얼로그                      | `shared/ui/`                                       |
| 범용 헬퍼·설정                            | `shared/lib/`, `shared/config/`                    |
| 탭 전환·계좌 복사                         | `features/project-tabs/`, `features/copy-account/` |
| 여러 기능이 공유하는 프로젝트 데이터 모델 | `entities/project/`                                |
| 여러 화면이 공유하는 상단바               | `widgets/site-header/`                             |
| 프로젝트 소개 화면 조합                   | `views/project/`                                   |
| 라우트·layout·전역 Provider               | `app/`                                             |

## 렌더링과 상태

- Server Component를 기본으로 하고, 이벤트·브라우저 API·클라이언트 훅이 필요한 최소 부분에만 `"use client"`를 선언합니다.
- v4의 프로젝트 설명, 단체 정보, 계획처럼 정적인 내용은 서버에서 렌더링할 수 있게 둡니다. 탭 전환과 클립보드 복사는 클라이언트 경계에 둡니다.
- 단일 화면의 지역 상태는 컴포넌트에 둡니다. 여러 화면이 상태를 공유할 때만 전역 store를 검토합니다.
- 서버 상태 라이브러리나 폼 라이브러리는 실제 API·검증 요구가 생긴 뒤 도입합니다.
- 화면은 로딩·오류·빈 상태·성공 상태가 필요한 데이터와 그렇지 않은 정적 콘텐츠를 구분합니다.

## 운영 정보와 데이터 경계

프론트엔드는 v4 디자인을 구현했습니다. 목표·일정·계좌는 운영자가 확인했으며 구글 폼은 비공개 시트에 연결했습니다. 명예의 전당에는 퍼즐을 표시합니다. Node.js 서버 함수가 서비스 계정으로 집계 탭만 읽고 `/api/funding`으로 총액·건수·동의한 이름을 전달합니다. 하나의 지역 상태가 히어로와 퍼즐에 결과를 공유합니다. 계정 설정 전에는 준비 안내와 초기 0원·0건을 표시합니다. [시트 연결 안내](funding-sheet-setup.md)와 [API 경계](api-boundary.md)에 실제 연결 절차와 계약을 기록했습니다.
