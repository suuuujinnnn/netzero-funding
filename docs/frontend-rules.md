# 프론트엔드 구현 규칙

`veily-web`의 React, 반응형, 접근성 원칙을 v4 화면에 맞게 옮겼습니다. 색상·폰트·버튼의 기준은 이 저장소의 [DESIGN.md](../DESIGN.md)이며, 원본 화면은 `docs/mockup/v4.html`과 `v4.css`입니다.

## 반응형과 레이아웃

- 모바일을 기본으로 구성하고 넓은 화면의 차이를 breakpoint로 확장합니다.
- 375×812, 768×1024, 1440×900 안팎에서 가로 넘침, 잘린 문구·버튼, 터치 영역, 긴 문단의 행 길이와 여백을 확인합니다.
- 헤더와 본문의 좌우 기준선을 맞춥니다. 여러 화면이 생기면 공통 폭 규칙을 한 곳에서 관리합니다.
- 목업 v4의 색상, 글자, 간격, 형태를 `DESIGN.md`에 따라 재사용되는 토큰으로 옮깁니다.

## 컴포넌트와 스타일

- 같은 feature의 구현, `widgets/`, `shared/ui/` 순서로 재사용할 수 있는 코드를 찾습니다.
- 의미와 동작이 반복되거나 독립된 상태를 소유하는 UI만 컴포넌트로 분리합니다. 짧은 일회성 마크업은 미래 가능성만으로 추출하지 않습니다.
- Tailwind와 테마 토큰을 우선 사용합니다. 조건부 class 조합이나 variant 도구는 실제 필요가 생길 때 추가합니다.
- 전역 CSS에는 토큰과 진짜 전역 규칙만 두고 화면 전용 규칙은 해당 화면에 가깝게 둡니다.
- 런타임 값이나 CSS 변수 전달을 제외한 반복적인 inline style은 피합니다.

## React와 상태

- Server Component를 기본으로 합니다. 탭 전환, 클립보드 접근 등 브라우저 동작만 최소 클라이언트 영역에 둡니다.
- `any` 대신 구체적인 타입 또는 `unknown`의 검증·좁히기를 사용합니다.
- 파일·디렉터리는 lowercase kebab-case, React 컴포넌트 이름은 PascalCase를 사용합니다. Next.js 예약 파일명은 프레임워크 규칙을 따릅니다.
- 지역 상태를 우선하고, 공유 클라이언트 상태나 서버 상태 관리 도구는 실제 요구가 생길 때 추가합니다.

## 접근성

- v4의 본문 바로가기, 탭과 패널 연결, 키보드 방향키·Home·End 동작을 유지합니다. 현재 URL 해시로 열린 탭을 복원하는 동작도 보존합니다.
- 의미 있는 heading 순서와 semantic HTML을 사용합니다. 모든 조작은 키보드로 가능해야 하고 focus가 보여야 합니다.
- 아이콘만 있는 버튼에는 접근 가능한 이름을 붙이고 상태·오류는 색상 외에 글로도 전달합니다.
- 의미 있는 이미지에는 정확한 대체 글을 쓰고 장식 이미지는 보조 기술에서 제외합니다.
- 움직임을 추가하면 reduced-motion 설정을 고려합니다.
