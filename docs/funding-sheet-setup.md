# 구글 폼·시트와 홈페이지 연결

폼 응답은 연결된 비공개 관리 시트의 `실제 응답`에 저장됩니다. 운영자는 입금 알림을 별도로 확인한 뒤 해당 행의 J 확인금액에 실제 금액을 입력하고 I 확인상태를 `확인 완료`로 변경합니다. 필요하면 K 정정입금일을 입력합니다. 원본 응답은 보존하고 중복 입금은 한 행만 확인합니다. 공개 동의가 `동의합니다` 하나인 확인 완료 건의 이름만 집계합니다.

## Apps Script 설정

1. netzero 계정으로 [관리 시트](https://docs.google.com/spreadsheets/d/1aAFvpV5t0_3YIngNYJspW6lffRnUx18n4YBeRjaMGgI/edit)를 열고 확장 프로그램 → Apps Script를 선택합니다.
2. [스크립트 코드](../apps-script/Code.gs)를 붙여 넣고 저장합니다. 이 코드는 `홈페이지집계`의 확인금액·확인건수·공개 동의 이름만 반환합니다. 원본 응답, 이메일과 운영메모는 반환하지 않습니다.
3. 배포 → 새 배포 → 웹 앱을 선택하고 실행 계정은 netzero 계정, 액세스는 모든 사용자로 설정합니다. 권한 요청 내용을 검토하고 승인합니다. 이 주소는 누구나 호출할 수 있으므로 배포 전 코드와 공개 결과를 확인합니다. 관리 시트 자체는 비공개로 유지합니다.
4. 배포된 `https://script.google.com/macros/s/.../exec` 주소를 로컬 `.env.local` 또는 Vercel Production의 서버 환경변수 `FUNDING_APPS_SCRIPT_URL`에 설정합니다. `NEXT_PUBLIC_` 접두사는 사용하지 않습니다. 배포 코드나 환경변수 변경 후 홈페이지를 재배포합니다. 스크립트 수정 시에도 새 버전을 배포합니다.

서버는 Google이 반환하는 `script.googleusercontent.com`의 리디렉션만 따라가고 집계 형식과 값을 검증합니다. 정상 집계는 인스턴스별로 최대 60초 보관하며 브라우저는 최초 진입 및 5분 간격에 `/api/funding`을 조회합니다. 갱신 실패 시 마지막 정상값을 유지합니다. Apps Script의 사용량 제한이나 권한 오류가 발생하면 갱신이 실패할 수 있습니다.

## 실제 연결 검증

배포 후 `/api/funding`의 `ready`와 시트 집계 일치를 확인합니다. 운영자와 합의한 비식별 테스트 응답을 제출하고 시트 저장 → 대기 제외 → 확인금액 입력 및 확인 완료 → 동의 이름 표시 → 정정·확인 취소 → 테스트값 제거를 확인합니다. 공개 Apps Script 주소와 브라우저 네트워크에 원본 개인정보가 없는지 확인합니다. 폼과 시트에서 테스트 응답을 각각 정리해야 합니다. 홈페이지 업데이트에는 캐시와 갱신 간격이 적용됩니다.
