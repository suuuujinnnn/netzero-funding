# 입금 확인과 홈페이지 집계 연결

프론트 구현은 완료했지만 실제 폼·시트 설정과 연결은 아직 수행하지 않았습니다. 초기 집계는 운영자가 확인한 0원·0건입니다. 아래 설정을 마쳐야 운영 데이터가 자동 반영됩니다.

## 1. 비공개 관리 파일

현재 구글 폼을 응답 스프레드시트에 연결합니다. 폼에는 입금자명·금액·입금일, 이름 공개 동의와 공개표시명을 추가합니다. 공개 동의는 필수 선택하되 ‘동의하지 않음’을 선택할 수 있어야 합니다. 공개표시명은 동의자만 입력합니다. 이름 공개와 기부 인증서용 이메일 수집은 별도 목적입니다.

응답 파일은 웹에 게시하지 않습니다. 현진 님 등 필요한 운영자만 편집 권한을 갖습니다. 같은 파일에 `입금관리` 탭을 만들고 다음 열을 사용합니다. 폼 원본과 관리 행은 응답 타임스탬프 등 식별값으로 대조하며 실제 계좌 거래 하나를 한 행으로만 집계합니다. 중복 폼 응답은 거래가 중복 합산되지 않도록 정리합니다.

| 열            | 값                         | 운영 규칙                           |
| ------------- | -------------------------- | ----------------------------------- |
| A: 확인금액   | 0 이상의 정수, 원 단위     | 실제 입금액을 확인한 뒤 정정        |
| B: 확인상태   | 입금 확인 대기 / 확인 완료 | 새 행은 대기. 빈 값도 집계에서 제외 |
| C: 공개동의   | 동의 / 동의하지 않음       | 빈 값은 비동의로 처리               |
| D: 공개표시명 | 동의한 이름                | 동의하지 않으면 비워 둠             |

오른쪽 열에는 비공개 입금자명·입금일·응답 식별값·검토 메모를 둘 수 있습니다. B·C는 드롭다운으로 제한하고 A는 정수·0 이상 검증을 설정합니다. 확인 대기 행도 시트에 남겨둡니다. 계좌와 대조한 뒤에만 B를 ‘확인 완료’로 바꿉니다. 확인 취소·금액 수정·행 삭제는 집계 감소로도 반영됩니다.

## 2. 공개 정보만 내보내기

**비공개 파일 안에** `공개내보내기` 탭을 만들고 A1에 아래 수식을 넣습니다. 이 탭은 세 열 이외의 데이터를 넣지 않습니다. 전체 원본을 공개 파일로 가져온 뒤 숨기거나 필터링하지 않습니다.

```text
=VSTACK(
  HSTACK("확인금액","확인건수","공개표시명"),
  HSTACK(SUMIF('입금관리'!B2:B,"확인 완료",'입금관리'!A2:A),COUNTIF('입금관리'!B2:B,"확인 완료"),""),
  IFERROR(FILTER(HSTACK(IF(ROW('입금관리'!D2:D),"",""),IF(ROW('입금관리'!D2:D),"",""),'입금관리'!D2:D),'입금관리'!B2:B="확인 완료",'입금관리'!C2:C="동의",'입금관리'!D2:D<>""),HSTACK("","",""))
)
```

총액·건수에는 이름 공개에 동의하지 않은 확인 완료 거래도 포함됩니다. 이름은 확인 완료·공개 동의·표시명 입력을 모두 만족한 행만 포함됩니다. 시트 순서와 같은 이름의 여러 기록을 유지합니다. 메시지·소속·개별 금액·입금일은 내보내지 않습니다.

## 3. 별도 공개용 파일

새 스프레드시트를 만들고 `홈페이지` 탭 A1에 다음을 입력합니다. 비공개 파일의 ID를 교체하고 운영자 계정으로 접근 허용을 승인합니다.

```text
=IMPORTRANGE("비공개_관리파일_ID","공개내보내기!A:C")
```

공개용 파일에는 `홈페이지` 탭만 둡니다. 파일 → 공유 → 웹에 게시에서 **홈페이지 탭만**, 형식은 CSV로 선택하고 수정 시 자동 재게시를 켭니다. 편집 권한은 운영자만 갖습니다. 원본 응답 파일을 게시하지 않습니다. 게시 주소에 접근할 수 있는 누구나 이름 목록을 다운로드할 수 있으므로 공개 동의가 필수입니다.

게시 결과는 다음 형식이어야 합니다. 총액·건수는 첫 데이터 행에만 들어가고 이후 이름 행의 두 칸은 비워집니다.

```csv
확인금액,확인건수,공개표시명
100000,3,
,,김하늘
,,이로운
```

연결 전 운영자가 별도 테스트 행으로 확인 대기 제외, 비동의 이름 제외, 정정·취소·삭제를 확인하고 테스트 행을 제거합니다. 실제 Sheets에서 수식·IMPORTRANGE·게시 갱신이 정상 동작하는지 확인해야 합니다. 게시 반영 시간은 즉시라고 보장하지 않습니다.

## 4. 프론트 연결

`.env.example`을 참고해 개발 환경 또는 Vercel 환경변수에 다음 값을 설정합니다. Google에서 제공한 게시 URL의 `gid`, `single` 값은 유지합니다.

```text
NEXT_PUBLIC_FUNDING_CSV_URL=https://docs.google.com/spreadsheets/d/e/게시_ID/pub?gid=시트_ID&single=true&output=csv
```

이 값은 비밀이 아니며 방문자에게 노출됩니다. 최초 주소 설정·주소 변경에는 빌드와 재배포가 필요합니다. 이후 데이터 수정에는 재배포가 필요하지 않습니다. 홈페이지는 첫 진입과 5분 간격에 CSV 전체를 다시 읽으며 히어로·퍼즐·이름 목록에 같은 데이터를 사용합니다. 퍼즐은 목표 800,000원에 대한 완성 조각 수를 내림 계산하며 목표 초과에도 최대 24조각입니다.

요청 실패·형식 오류·잘못된 숫자는 실적 0원으로 처리하지 않습니다. 처음 연결 실패 시 불러오기 실패를 표시하고, 이후 실패는 마지막 정상값을 유지하며 다음 주기에 다시 요청합니다. 마지막 조회 시각은 입금 시각이나 은행 검증 시각이 아니라 CSV 조회에 성공한 한국 시간입니다.

실제 게시 CSV의 브라우저 접근과 갱신은 연결 후 검증해야 합니다. CORS나 조직의 게시 제한으로 접근이 막히면 프론트만으로 비공개 원본을 우회하지 않고 공개 설정을 확인합니다. 외부 시트 생성·수정, 실제 입금 확인과 Vercel 배포는 이번 코드 작업에 포함하지 않았습니다.
