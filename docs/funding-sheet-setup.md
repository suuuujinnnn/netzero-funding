# 구글 폼·시트와 홈페이지 연결

폼 응답은 연결된 비공개 관리 시트의 `실제 응답`에 저장됩니다. 운영자는 입금 알림을 별도로 확인한 뒤 해당 행의 J 확인금액에 실제 금액을 입력하고 I 확인상태를 `확인 완료`로 변경합니다. 필요하면 K 정정입금일을 입력합니다. 원본 응답은 보존하고 중복 입금은 한 행만 확인합니다. 공개 동의가 `동의합니다` 하나인 확인 완료 건의 이름만 집계합니다.

## 최초 연결

1. Vercel의 넷제로 펀딩 프로젝트에서 **Storage → Create Database → Blob**을 선택하고 **Private** 저장소를 Production에 연결합니다. 프로젝트 서버 환경 변수에 `BLOB_READ_WRITE_TOKEN`이 추가됐는지 확인합니다.
2. 충분히 긴 무작위 비밀값을 생성해 Vercel Production 서버 환경 변수 `FUNDING_SYNC_SECRET`에 저장하고 홈페이지를 배포합니다.
3. 관리 시트에 접근할 수 있는 netzero 계정으로 [Apps Script](https://script.google.com/)에서 독립형 프로젝트를 만들고 [스크립트 코드](../apps-script/Code.gs)를 붙여 넣습니다. 스크립트 수정 권한은 운영 계정에 둡니다. 시트 팀원은 기존 시트 편집 권한으로 입금을 확인합니다.
4. Apps Script **프로젝트 설정 → 스크립트 속성**에 `FUNDING_SYNC_URL`을 실제 운영 사이트의 `https://<운영 도메인>/api/funding`으로 지정하고, `FUNDING_SYNC_SECRET`에 Vercel과 같은 값을 저장합니다.
5. 편집기에서 `installFundingSync`를 한 번 실행하고 권한을 승인합니다. 이 실행이 최초 집계를 저장하고 편집 트리거와 5분 간격의 재확인 트리거를 설치합니다. 이후에는 입금 확인 때마다 자동 갱신됩니다.

기존 웹 앱에서 전환하는 경우 새 `GET /api/funding` 응답이 정상임을 확인한 뒤 기존 Apps Script 웹 앱 배포를 보관 처리하고 Vercel에서 `FUNDING_APPS_SCRIPT_URL`을 제거합니다.

## 실제 연결 검증

`GET /api/funding`이 `ready`를 반환하고 금액·건수·공개 이름이 시트와 일치하는지 확인합니다. 합의한 비식별 응답으로 확인 완료, 정정, 확인 취소를 각각 검증하고 폼과 시트에서 검증값을 정리합니다. 즉시 반영되지 않으면 Apps Script의 **실행 기록**을 확인합니다. 편집 직후 집계 수식에 반영되지 않았거나 일시 오류가 있었으면 주기 조회가 다시 확인합니다. 저장소 교체나 집계 파일 복구가 필요할 때는 운영 계정에서 `installFundingSync`를 다시 실행합니다.
